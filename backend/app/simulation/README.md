# backend/app/simulation

The simulator (`dev_docs/architecture/demo.md`): infrastructure, not an agent. It moves simulated time, plays the
outside world (shop floor, suppliers) and fires triggers; agents decide every response. Built so far: clock, settings,
the day cycle with Play / Pause, the simulated shop floor, suppliers and customers (structured or chat), triggers, saved starting states, the
default demo factory, scenarios, runs and run reports.

| File | Purpose |
| --- | --- |
| `factory_a.py` | The default demo factory (demo.md §4.1): items, BOMs, routings, stock, work centers, workers, zones, suppliers and Sales' products, built through each owner's own setup. |
| `models.py` (rule profile) | `RuleValue` / `RuleChange` (`simulation.rule_values`, `simulation.rule_changes`, migration 019): the user's business-rule values and their history; kept across restores (`states.KEPT`), re-applied by `states.restore` (RE-6). |
| `scenarios.py` | Built-in scenarios ONE (one order end to end, SIM), S1–S8, MANUAL and LOAD-10/20/100 (state + settings + triggers on run days + seed); `start` (restores the scenario's starting state, building it once if missing: `factory-a`, or for a load run `factory-a-load-N` with finished phones and tablets for about 75% of its expected orders (`LOAD_COVER`) and room for them, schedules the triggers, opens a run), `finish` (saves the run report: metrics, orders, triggers, final factory state, the whole timeline). |
| `models.py` | `Clock` (one row: current simulated day, status: PAUSED / RUNNING (Play)), `Setting` (versioned factory settings) `TriggerLog` (every trigger, fired now or scheduled for a day; migration `012`), `Snapshot` (014), `Run` and `RunReport` (016; kept across restores) in the `simulation` schema. |
| `clock.py` | SIM-1: `current_hour`, `shift` (`shift_start`, `shift_hours`), `advance_hour`; a new day starts at the shift's start (migration 020).  `get_clock` (created on first use at `simulation_start_day`), `today`, `next_day` (locks the clock row, advances one day, publishes `SimulatedDayStarted` in the same transaction). |
| `settings.py` | `DEFAULTS` (every factory setting with its documented default and decision id), `read_settings` (values + version), `setting`, `update_settings` (validated; one new version per change). |
| `suppliers.py` | Simulated suppliers (PI-1): answer Purchasing's offers automatically through the supplier chat path, in Purchasing's strict format; deterministic (accept what they can meet, else counter with their available quantity by their earliest date). Work item `SUPPLIER_TURN` of the Purchasing adapter's queue. Setting `simulated_suppliers` (1 on, 0 = a person answers). |
| `customers.py` | Customer driver, structured mode (DM-3, DM-7): `customer_orders_per_day` new requests each morning (seeded per day, DM-6), then the fixed decision rule on Planning's answers (accept REQUESTED, else LATER_DATE up to `customer_later_date_max_days`, else decline). Only through Sales' doors (HTTP). Off by default (0 orders a day). `customer_order_days` > 0 bounds a load run: customers order only on the run's first N days (`ordering_on`). Chat mode (`customer_chat_mode` 1): customers write test-chat messages that Sales reads with the model, then answer with a letter and "yes". |
| `shop_floor.py` | Simulated shop floor (RD-3, SIM-2): hour by hour, each released order works the machine-hours Planning scheduled per day, spread evenly over the shift; finished units are reported in batches (`production_batch_size`, a Planning rule) — every batch but the last becomes `ProductionBatchCompleted` and is stored at once, the last one `ProductionCompleted`. `work_hours(db, day, until_hour)`, `report_day` (the whole shift). Fixed report ids (a repeat changes nothing). |
| `runner.py` | SIM-1: `run_one_hour` (one working hour; at the shift's end it starts the next day first) and Play = one hour per tick (`seconds_per_sim_hour`); `run_one_day` = start the day and work the whole shift.  The day cycle: advance the clock and fire the triggers due → customers' requests → wait until quiet → customers decide → wait until quiet (no PENDING/RUNNING work in any queue) → shop floor → wait until quiet. A day that does not become quiet within `quiet_limit_seconds` pauses Play and reports what is waiting. `work_left` (open demands, scheduled triggers, customers still ordering tomorrow): when empty, Play pauses by itself (`pause_reason`). Play / Pause (one background thread; the clock row holds the status). |
| `triggers.py` | Triggers through the owner's input (demo.md §7): `NEW_ORDER`, `CANCEL_ORDER`, `CHANGE_ORDER` (Sales' simulated-customer doors), `WORKER_ABSENT` (HR), `SUPPLIER_DELAY` (Purchasing; by delivery or "next delivery of an item"), `WAREHOUSE_CAPACITY` (Warehouse's `change_capacity`, S4). Now or scheduled; logged; an owner's refusal is recorded as FAILED. |
| `states.py` | Starting states (DM-2): `save` (only when quiet; every run table as JSON, failed work not saved), `restore` (one transaction: empty, load, counters, clock paused) and every owner's `reconcile` check. |
| `api.py` | Doors: `GET /simulation/clock` (day, status, what is waiting, `pause_reason`, `work_left`), `POST /simulation/clock/next-day` (one day cycle in the background), `/clock/play`, `/clock/pause`, `GET`/`POST /simulation/settings` (K), `POST /simulation/triggers` (K, now or `day`), `GET /simulation/triggers`, `POST /simulation/states` (K, save), `GET /simulation/states`, `POST /simulation/states/{name}/restore` (K), `POST /simulation/factories/factory-a` (K, configure), `GET /simulation/scenarios`, `POST /simulation/scenarios/{name}/start` (K), `GET /simulation/runs`, `POST /simulation/runs/{id}/finish` (K), `GET /simulation/runs/{id}/report`. Setting `ai_enabled` switches the agents' AI steps on. |

**Tests:** `test_scenarios.py` (S1 from start to report), `test_simulation_states.py` (restore + reconcile + replay), `test_customer_driver.py` (a simulated customer's order from request to shipment by the simulator alone); the day cycle and shop floor run in every end-to-end test (`tests/platform/phone_factory.py` `run_day`); triggers in the S2 test (`test_supply_flow.py`); S4 in `test_receiving_slots.py`, S8 in `test_competing_orders.py`.
